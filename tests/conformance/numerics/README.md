# Python-authored numeric conformance

Format 1 is defined in `autophys.project.docs/content/rust-sdk.md`; the binding
reader is `sdks/rust/tests/numerics.rs`. The model/operation JSON cases are generated by
`sdks/python/tests/numerics_cases.py`. From `sdks/python`, with the [contributor environment](../../../CONTRIBUTING.md) active, explicitly regenerate with:

    PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python tests/numerics_cases.py

Run `tests/test_numerics_conformance.py` with pytest to recompute from the stored
inputs and apply the same comparison rules as Rust. It also checks that the
generator still produces the same case coverage, comparison rules and expected
values within those rules. No solver evaluation counts, solver status codes,
messages, timing, record IDs or timestamps are compared.

Each model has `simulate-compact`, `fit-compact`, `analyze-compact`,
`rank-compact` and `outlook-compact`. All three also have `run-scripted`; oscillator and thermal have `run-policy`,
and thermal and battery have `analyze-short` and `rank-short`. Discover current
inputs with `git ls-files tests/conformance/numerics` from the repository root. Every input includes its parameter schema, experiment catalog,
solver options and truth/estimate. Observations contain actual numeric arrays,
generated with NumPy seed 20261104 and TRUTH_OPTIONS. Each fit uses an explicit
off-truth start (truth multiplied by 1.1), disables Python random starts, and
compares success and bound membership exactly.

| Operation | Models | Compared output | Rule |
| --- | --- | --- | --- |
| simulate | thermal, oscillator, battery | full trajectory including time | rtol 1e-6, atol 1e-9 |
| fit | thermal, oscillator, battery | params, loss, chi2_per_n | rtol 1e-5, atol 1e-8 |
| fit | thermal, oscillator, battery | success, at_bounds | exact |
| analyze | thermal, oscillator, battery | identified, non_identified | set |
| analyze | thermal, oscillator, battery | singular_values | rtol 1e-5, atol 1e-7 |
| analyze | thermal, oscillator, battery | weighted residual Jacobian | rtol 1e-5, atol 1e-6 |
| analyze | thermal, oscillator, battery | each singular direction vector | up_to_sign, rtol 1e-5, atol 1e-7 |
| rank | thermal, oscillator, battery | order | exact |
| outlook | thermal, oscillator, battery | axes; score and after arrays | exact axes; rtol 1e-5, atol 1e-7 |
| run | oscillator, thermal | final status; ordered actions and decision arguments | exact |

Outlook has a three-point single axis (thermal power, oscillator amplitude,
battery current). Run cases use Python ScriptedPolicy with seed 0 and a
noise-free deterministic runner at the supplied truth. The `run-scripted` reader replays the saved decision transcript through SequencePolicy. Python independently
reruns ScriptedPolicy and checks its semantic transcript against the saved
script. Decision evidence prose contains formatted solver results and is
excluded. Both runs finish validated after fit, analyze, rank, request, refit,
analyze, validate, stop. These fixtures test orchestration and declared comparisons, not independent
validation quality; some reuse the initial measurement as validation.
All compact analyze cases identify every free parameter. `thermal/analyze-short`
is the degenerate case: a 120 s step against a 1000 s time constant determines C
but leaves R non-identified; `thermal/rank-short` then ranks the long step first.

`run-policy` cases carry a top-level `"policy": "scripted"` and no `script`: the
reader runs its own ScriptedPolicy and must produce the same decisions and final
status. `run-scripted` cases keep replaying the saved script.

Reader boundaries: analyze/rank/outlook do not read the supplied solver options,
so these cases use FIT_OPTIONS throughout those operations. The run reader applies supplied budgets and stop/stop_rules, but does not
select run noise/bias configuration or n_starts; it uses bias=off and the
Project's four-start default. Python outlook exposes after_resolved_max/at and
budget/scale controls which this reader does not parameterize; only axes,
score and after are compared. No minimum-coverage case had to be omitted.

Historical validation on rwc-dev-01 (2026-11-04), not current-artifact acceptance: the original 17 cases passed the unmodified Rust
numerics_conformance reader, with no tolerance loosening.

The Rust reader recursively discovers JSON cases and fails when the corpus is
missing or empty. Python checks current generator coverage and recomputes stored
inputs. See the [shared fixture inventory](../README.md) for workbook, replay,
price, chain and private display references. Regeneration is explicit; ordinary
checks leave these scientific goldens unchanged.
