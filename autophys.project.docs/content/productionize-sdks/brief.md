## Rust and Python must remain analogous

Operator steering before baseline qualification: “consider that rust and python need to be analogous.” Analogy is a first-class acceptance contract, not just similarly named functions. Corresponding operations must preserve concepts, schemas, defaults, error meaning and observable effects. Rust traits, `Result`, ownership and distinct method names may replace Python decorators, exceptions, context managers and optional arguments. Identical source or floating-point text is not the requirement; justified tolerances and scientifically equivalent conclusions are. Different simulator source bytes may correctly produce different source hashes and config versions; identical canonical config bodies must still hash identically. Python currently declares Apache-2.0 while Cargo declares UNLICENSED/publish=false; this is an observed packaging/release asymmetry requiring a justified disposition, not permission to change a license.

| Capability/concept | Python surface | Rust surface | Evidence and unresolved proof |
| --- | --- | --- | --- |
| Simulator and trajectory | `simulator`, `Simulator`, `ParamSpec`, `SimOptions`; `SimulationResult.u` | `simulator::{Simulator, FunctionSimulator, ParamSpec, SimOptions}`, trajectory input channels | Shared numerical `simulate` cases; declared-order coordinates and error/budget behavior need explicit review |
| Project/config/defaults | `project.Project`, `Budgets`, `NoiseConfig`, `StopRules`, `PolicyConfig` | `project` equivalents, `Project::new` then validation | Inspected defaults agree: 24 steps, 20,000 simulations, 2 experiments, 50,000 outlook calls; no test-hour cap; 4 starts; compare bias; scripted/low/2400 policy; thresholds 2.0. Rust mutable fields make validation timing a material difference to examine |
| Solver/default tolerances | `FIT_OPTIONS` 1e-8/1e-10; `TRUTH_OPTIONS` 1e-11/1e-13 | same named constants and values | Source agrees; shared fit/analyze/rank/run cases use per-field tolerance/sign/set rules rather than exact solver iteration counts |
| Fit, sensitivity, experiment selection | `fit`, `analyze`, `rank_experiments`, `design.outlook`; oscillator/thermal/battery models | `fit::fit`, `sensitivity::analyze`, `design` functions and `models` | Shared JSON numerical cases and candidate/battery/curves/display tests. Rust linear algebra/native solvers versus NumPy/SciPy is intentional; status, diagnosis, bounds and ranked experiment semantics must agree |
| Local/remote connections | `connect(target, api_key=...)`, `LocalClient`, `RemoteClient` | `connect(Option<&str>)`, `Client::connect_remote` and remote adapter | Same collection/file/URL concepts and `AUTOPHYS_HOME` default. Inspect normalization: Rust lowercases URL scheme and treats empty target as default; Python's prefix matching and empty path differ. This is an observed source-level difference, not yet accepted rationale |
| Project/investigation access | `client.project(Project or str)`, `wb.investigation(... runner/policy ...)`, `inv.run` | `project`/`project_with`, `investigation`/`resume`, `run` | Different method arity is idiomatic and documented; record/config pinning and approval/resume effects must agree |
| Persistence and wire data | `WorkbookStore`, `MemoryStore`, `JsonlStore`, canonical/hash helpers, `HttpStore` | workbook/record/canonical/schema modules, remote workbook adapter | Shared `.ap-workbook` format-1 goldens and chain vectors; root HTTP tests and cross-writer suite. | Validation and errors | `WorkbookError`, `StoreError`, `HttpError`; numeric `BoundsError`, simulation/budget exceptions | `error::Error`, `remote::HttpError`, `SimulationError` variants with `Result` | Compare error code/status/path and transactional effects, not exception class spelling. Fresh probes confirm this constructor/validation difference; consequence still requires review. | Tools around the library | CLI bench/research/export, plots, optional MCP/Muse | no dedicated SDK CLI/plots/MCP/research counterpart identified; daemon is a separate consumer | These are observed asymmetries, not invented Rust APIs. Treat as explicit gaps needing operator/product interpretation where material; Python-only tooling may be intentional but rationale is not established by naming alone |
